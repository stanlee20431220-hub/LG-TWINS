# 재고 모니터링

GitHub Actions에서 상품을 조회하고 Google Sheets에 옵션별 결과를 저장합니다. 텔레그램에는 중요한 변동 요약과 시트 링크만 전송합니다. 시트 연결이 실패하면 기존 전체 알림 방식으로 자동 대체합니다.

## 실행
- 매일 한국 시간 09:15 예약 실행 (GitHub 상황에 따라 지연될 수 있음)
- Actions > Baseball Stock Monitoring > Run workflow에서 수동 실행 가능
- 동시 실행은 순서대로 처리합니다.

## 필요한 Actions Secrets
- TELEGRAM_BOT_TOKEN
- TELEGRAM_CHAT_ID
- GOOGLE_SERVICE_ACCOUNT_JSON: 서비스 계정 JSON 전체. 저장소 파일에는 절대 넣지 않습니다.
- GOOGLE_SHEET_ID: 전용 스프레드시트 ID

Google Cloud에서 Sheets API를 활성화하고 서비스 계정 이메일을 전용 시트의 편집자로 공유합니다. 서비스 계정에 Cloud 프로젝트 관리자/편집자 역할은 필요하지 않습니다.

## 데이터 해석
- 옵션 하나당 한 행, 총 13열: 상품명, 옵션, 수량, 상품 링크, 이미지, 확인 시각, 이전 수량, 증감, 상태, 가격, 출처 도메인, 구매제한, 수량 근거.
- 수량은 재고관리 활성 상태에서 확인된 서버 재고값만 숫자로 표시합니다. 정확한 서버 재고가 9999라면 숫자 9999로 표시되며 이는 검증된 값이고 무한재고 표기가 아닙니다.
- 판매 상태와 수량 확인은 별개입니다. 명시된 품절은 품절/0으로, 비노출·판매중지 옵션은 구매불가로 표시합니다. 선택 가능하더라도 정확한 수량 조회가 실패할 수 있으며 이를 품절로 바꾸지 않습니다.
- 기존 조회 코드를 유지한 우선순위: 명시적 DOM 품절 → 비노출/판매중지 → 주문제작·재고 미관리·구매제한 정책 → 페이지의 정확한 재고값 → 기존 CalculatorProduct → 동일 컨텍스트 API 재확인 → 상품 페이지 브라우저의 네이티브 XMLHttpRequest 자동 재확인 → 선택적으로 제공된 정상 브라우저의 검증된 서버 응답. 선택지 DOM이 없는 경우에 한해 동일 상품·품목으로 검증된 JSON-LD 판매 상태를 보완 근거로 사용합니다. JSON-LD InStock을 숫자 재고로 환산하지 않습니다.
- 구매제한은 재고가 아닙니다. 구매제한이 있는 경우 별도 열에 제한값을 표시하고, CalculatorProduct의 주문가능 수량을 재고로 환산하지 않습니다. 실제 재고 수량은 미공개로 표시합니다.
- 주문제작 및 재고 미관리 옵션은 수량 없음으로 표시합니다. 재고 수량은 미공개하거나 알 수 없는 옵션은 미공개/확인불가로 표기하며 0으로 간주하지 않습니다. DOM의 명시적인 품절 표시는 0으로 처리합니다.
- 관리 재고의 서버값이 없으면 제한된 동일 컨텍스트 API 확인을 재고관리 활성·제한 없음인 옵션에만 적용합니다. API 리디렉션·HTML 응답·통신 실패는 수량 열에 수량 미확인으로 표시하고, 선택 가능한 옵션의 상태는 구매가능 · 수량조회실패로 표시합니다. 수량 근거 열에는 실패 이유를 남깁니다. 이 상태는 품절이나 실제 재고 미공개를 의미하지 않습니다.
- 브라우저 XMLHttpRequest 자동 재확인은 기존 조회가 모두 실패한, 선택 가능한 재고관리 활성·구매제한 없는 옵션에만 실행합니다. 사이트의 실제 GET CalculatorProduct 요청을 브라우저에서 직접 전송하며, 동일 출처·API 경로·JSON·상품/품목 코드와 명시적 stock_number를 검증합니다. 요청값 9999나 화면에 입력된 수량은 재고로 사용하지 않습니다. 성공하면 시트 근거에 `브라우저 XHR 서버값 · 자동 재확인`과 실제 수량 확인 시각을 기록합니다. 이 단계는 수동 JSON 없이 예약 실행에도 작동하지만, GitHub 브라우저에서도 리디렉션·HTML이 반환되면 수량 미확인으로 남깁니다. 별도 실행환경·프록시나 수량 고정값은 추가하지 않습니다.
- 수동 실행의 browser_stock_evidence 입력은 선택 사항입니다. schema 1의 captures 배열에 정상 브라우저에서 받은 실제 API 응답·요청/응답 URL·상품/품목 코드·UTC 확인 시각을 전달합니다. 기존 조회가 실패한 재고관리 활성·구매제한 없는 선택 가능 옵션에만 사용하며, 상품/품목/호스트/경로/JSON 일치와 해당 구단 조회 프로세스 시작 시점 기준 10분 이내 시각을 검증합니다. 오래되거나 미래이거나 불일치한 증거는 무시합니다. 숫자를 직접 고정하지 않으며, 시트 확인 시각에는 원래 브라우저 수량 확인 시각을 기록합니다. 입력이 없는 예약 실행에서는 이 경로가 자동으로 제공되지 않습니다.
- API 재확인에는 상품 페이지 Referer와 일반 XMLHttpRequest 요청 헤더를 사용합니다. 타 호스트 리디렉션이나 HTML은 재고로 해석하지 않습니다. 사이트 차단이 계속되면 수량을 추정하거나 수동 고정하지 않습니다.
- 제품 번호 2812의 주문제작 처리는 nolmdshop.com에서만 사용자 지정 예외로 적용됩니다. 페이지 푸터 문구만으로 주문제작을 추론하지 않습니다.
- 오류·이전 데이터: 새 조회가 실패하여 마지막 기록을 유지한 행입니다. 오류·불확실·이전 형식 데이터는 재고 증감·품절·재입고 판단에서 제외됩니다.
- 기존 history의 스키마가 2가 아니거나 옵션 근거가 없는 과거 수량은 비교 기준으로 쓰지 않습니다. 첫 스키마 2 실행은 새 기준을 설정하며 재입고 알림을 만들지 않습니다.
- 증감은 판매량이 아닙니다. 누락된 이미지나 외부 이미지 접근 제한 시 썸네일이 표시되지 않을 수 있습니다.

시트의 자동 관리 탭에는 수동 데이터를 넣지 마세요. 수동 메모는 별도 탭에 보관하세요.


## 구단별 탭

스프레드시트 `재고 모니터링`의 `LG트윈스`, `두산베어스`, `키움히어로즈` 탭을 각각 갱신합니다. 매일 09:15에 세 구단을 순차 조회하며 각 구단별 이력을 따로 보관합니다. LG는 기존 트윈스코어샵과 NOL MD 조회를 유지합니다. 두산(NOL 카테고리 30)과 키움(NOL 카테고리 29)은 NOL MD 공식 판매 목록을 조회합니다. `STOCK_TEAM`으로 개별 구단을 선택할 수 있습니다. 한 구단이 실패해도 다음 구단을 조회하며 실패 상태를 최종 실행 결과에 남깁니다.


## 사용자 브라우저 자동 보완

Aside가 실행 중인 사용자 기기에서 실패 옵션을 실제 브라우저의 native XHR로 확인하고, 최신 검증 응답을 구단별 수동 실행 입력으로 자동 전달합니다. 기존 GitHub 조회를 먼저 유지하며 실패한 옵션만 검증 근거로 보완합니다. 데이터 확인 시각은 원래 서버 응답 시각입니다. 기기가 꺼져 있거나 Aside가 실행되지 않으면 이 보완은 실행되지 않으며 미확인 상태를 그대로 표시합니다. NOL의 숨겨진 더보기 제어를 순차 실행해 목록 마지막 페이지까지 수집하며, 페이지 진행 실패는 전체 조회 실패로 처리하여 기존 시트를 보존합니다.


### 완전한 목록과 대용량 검증 응답

정상 사용자 브라우저에서 마지막 더보기 페이지까지 확인한 완전한 NOL 상품 목록도 최신 검증 입력에 함께 전달할 수 있습니다. GitHub의 목록 수집이 실패할 때만 이 목록으로 불완전한 결과를 교체하며, 구단 카테고리·상품 주소·페이지 완료·구단 프로세스 시작 기준 10분 이내 확인 시각을 검증합니다.

대량 옵션의 원본 JSON이 GitHub 입력 크기 한도를 넘을 경우 `{schema:1, encoding:"gzip+base64", data:"..."}` 압축 봉투를 사용합니다. 원래 API 응답, 요청/응답 주소와 확인 시각을 손실 없이 유지하고, 해제된 JSON에는 기존 검증을 그대로 적용합니다. 입력과 압축 해제 결과는 각각 1,000,000바이트까지 허용하며 손상된 압축, 중첩 봉투와 과도한 확장 입력은 거부합니다. 압축은 오래된 확인 시각을 새로 만들지 않습니다.

사용자 브라우저 자동 보완은 Aside와 브라우저가 실행 중일 때만 동작합니다. 기기가 꺼진 동안에도 GitHub의 기존 예약 조회는 계속되지만, 정상 응답을 받지 못한 수량을 추정하거나 0으로 바꾸지 않습니다.
